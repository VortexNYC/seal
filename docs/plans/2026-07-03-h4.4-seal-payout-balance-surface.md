# H4.4 — Seal payout/balance surface reads REAL per-user Vortex settlements/payouts

**Why:** Vortex now reliably projects real Finix settlements + merchant payouts (H4 cron, live-proven: 60 settlements + 18 merchant payouts, platform excluded). Seal's payout/balance UI still shows a LOCAL placeholder and `getMerchantAccount` reads `retired_provider_accounts`/`retired_providerAccountId`. H4.4 wires Seal to display the merchant's REAL Vortex payout/settlement data. This is the user-facing "payout visibility" 1c wanted, now unblocked. Seal → Vortex PUBLIC API only (never Finix).

## Grounding
- Vortex read endpoints (public): `/v1/merchant-accounts/:id/settlements`, `/payouts`, `/payout-profile` (routes.ts:95-131). NO dedicated /balance endpoint → balance is DERIVED (e.g. settled-not-yet-paid-out) from settlements/payouts; keep honest.
- Seal has `readRemoteVortexMerchantState` (vortex_merchant_actions.ts:211) reading /state+/capabilities via `requestVortexBillingJson` — mirror it for /settlements + /payouts.
- Seal `merchant_account_queries.getMerchantAccount` reads `retired_provider_accounts` + returns `processorAccountId: retired_providerAccountId` (:18/:41). Allowlisted orgs have a Vortex merchant on the row (provider="vortex", vortexMerchantAccountId).
- UI: `payouts.tsx`/`balances.tsx` → `VortexMerchantOperationalSurface` renders LOCAL placeholder (zero balance, readiness from payoutsEnabled); `VortexBalanceWalletPanel` local zero state.

## Scope (Seal only; boundary = Vortex public API)
1. **New Seal read action(s)** in vortex_merchant_actions.ts (mirror readRemoteVortexMerchantState): `getVortexMerchantPayoutData(organizationId)` → for the org's Vortex merchant, GET `/settlements` + `/payouts` (+ `/payout-profile`) via requestVortexBillingJson; return a neutral shape { settlements[], payouts[], payoutProfile, derivedBalance }. Guard: only allowlisted orgs with a charges-ready Vortex merchant; else return null/empty (honest).
2. **Fix `getMerchantAccount`** (or add a provider-aware path) so allowlisted/Vortex orgs resolve the Vortex merchant id + provider="vortex" (not retired_providerAccountId). Keep retired provider orgs unchanged.
