## Global Constraints
- **MONOTONIC ORDERING GUARD (Codex L4 finding #7 — required, money-state correctness).** Vortex webhooks have NO cross-event ordering guarantee, and Seal's `projectSubscriptionUpdated` has no stale-event protection (Vortex's own projection guards via `createdAt`). Without this, a stale `subscription.updated(active)` arriving after a newer `invoice.payment_failed` would wrongly re-activate a past-due sub (revenue leak). Fix: add an optional `lastSourceEventAt?: number` (ms) to the `subscriptions` schema; EVERY Vortex projection (subscription.updated AND invoice.paid/payment_failed) parses the envelope's `createdAt` → ms, and BEFORE writing, if the matched sub has `lastSourceEventAt` and `incomingCreatedAtMs < lastSourceEventAt`, SKIP the write (stale event) — else apply and set `lastSourceEventAt = incomingCreatedAtMs`. If the envelope has no `createdAt`, apply best-effort (current behavior) but do not advance the marker. This makes per-subscription Vortex projection monotonic. Idempotency (eventId dedup) still applies on top.
- **Mirror retired provider exactly** (`retired_provider/handlers.ts`): `invoice.paid` → patch matched sub `latestInvoiceId = invoice.invoiceNumber`, `latestInvoiceStatus = "paid"` ONLY (do NOT touch `status`, do NOT advance period — period advance stays on `subscription.updated`/`renewed`). `invoice.payment_failed` → patch `status = "past_due"` + `latestInvoiceId`/`latestInvoiceStatus`.
- **Correlation guard (risk a):** match sub via `subscriptions.by_external_subscription_id` using `invoice.subscriptionExternalId`. `subscriptionExternalId` is OPTIONAL on `InvoiceResource` — if ABSENT, early-return `{received:true, ignored:true}` (do NOT fall back to `customerExternalId`). If present but no sub row matches, no-op gracefully (no throw — mirror retired provider `handlers.ts:400/448`).
- **Ordering safety (risk c):** invoice handlers only NARROW (`payment_failed`→`past_due`); never WIDEN to active. Activation/period stay owned by `subscription.updated`. `invoice.paid` does NOT set status.
- **No invented mappings (risk b):** every other event type (`invoice.created/finalized/voided/marked_uncollectible/refunded/payment_requested`, `payment_request.*`, `partially_paid`, etc.) keeps returning `ignored:true`.
- **Equal-millisecond tie-break (Codex L4 r2 #2):** Vortex stamps `createdAt` via `Date.now()` ms; two events can share a ms. The guard skips only `incoming < stored`. To close the revenue-leak direction at equal ms: `projectSubscriptionUpdated` must NOT WIDEN status `past_due → active` when `incomingCreatedAtMs <= lastSourceEventAt` (only widen on STRICTLY newer). Invoice handlers only narrow (`payment_failed → past_due`) so they're safe at equal ms. Two strictly-same-ms events in the benign direction = accepted residual (documented).
- **Idempotency + dedup discipline (Codex L4 r2 #4):** reuse `vortex_billing_webhook_events` dedup on `eventId`, but ONLY insert the dedup row when the event is CORRELATABLE and processed (applied, or deliberately skipped-as-stale for a MATCHED sub). For an UNCORRELATABLE event (no `subscriptionExternalId`) or a not-yet-existent sub row → return `ignored:true` WITHOUT inserting the dedup row, so a later redrive (sub appears / corrected payload) can still process it (mirrors unknown-types not deduping today).
- No `any`/eslint-disable. Gate from Seal ROOT: typecheck, lint, targeted vitest. Do NOT touch the retired provider webhook path, `vortex_billing_processor.ts`, or `selectSaasBillingProvider`.
