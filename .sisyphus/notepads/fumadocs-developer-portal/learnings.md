### Key Learnings

  - TypeScript LSP initially couldn't resolve it (module not found error)
  - Solution: The module resolves correctly at runtime despite LSP warnings during development
  - No type declaration file needed - Vite plugin handles it
- **Import Pattern**: Different projects use different import paths:
  - `@/.source` (requires @ alias pointing to root)
  - `@/.source/server` (with /server suffix)
  - `../../.source/server` (relative path)
  - `fumadocs-mdx:collections/server` (virtual module - preferred)
  - We used the virtual module pattern as it's the most portable

- **Generated Files**: The `.source/` directory is auto-generated by Fumadocs MDX Vite plugin
  - Contains: server.ts, browser.ts, dynamic.ts
  - These files have `@ts-nocheck` and are not meant to be imported directly
  - The virtual module abstracts away the implementation details

### Critical Discovery: MDX Plugin Configuration

The fumadocs-mdx Vite plugin requires the source config to be passed explicitly:

- **Incorrect**: `await mdx({})` - plugin doesn't find docs
- **Correct**: `await mdx({ docs: docs })` - plugin discovers and generates collections

### Key Learnings

1. **Virtual Module Resolution**: The `fumadocs-mdx:collections/server` virtual module is only generated when:
   - The source config is passed to the mdx plugin
   - The plugin option `updateViteConfig: true` is set (enables virtual module resolution)
   - The .source directory is regenerated with proper exports

2. **Build Configuration**: Production build requires special handling:
   - Virtual module must be added to `build.rollupOptions.external`
   - Without this, Rollup fails to resolve the virtual module during build
   - Solution: `external: ["fumadocs-mdx:collections/server"]`

3. **Dev vs Build**:
   - Dev server: Virtual module resolves correctly with updateViteConfig: true
   - Build: Requires external configuration to prevent Rollup errors

### Vite Config Changes Applied

```typescript
// Import source config
import { docs } from "./source.config";

// Pass config to mdx plugin with updateViteConfig option
await mdx({ docs: docs }, { updateViteConfig: true })

// Add virtual module to external list for build
build: {
  rollupOptions: {
    external: ["fumadocs-mdx:collections/server"],
    // ... rest of config
  }
}
```
