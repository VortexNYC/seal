# Production checklist

For teams on **seal.nyc** (hosted) or a serious self-host. Agents and humans both
use this as the “are we ready?” gate. Agents run the sender side via OpenAPI;
recipients (humans) sign. See [Agents & who signs](/getting-started/agents).

## Golden path (must work)

1. Create workspace
2. Create API key (`seal_…`) with document + recipient write scopes
3. Upload PDF → add recipient → send (agent / API / MCP)
4. Recipient opens signing link → **human** signs
5. Webhook (or poll) sees lifecycle events — at minimum `document.completed`;
   many integrations also use `recipient.viewed` / `document.viewed` for
   funnel tracking and `recipient.signed` before completion
6. Audit log shows the trail

Hosted golden path (from the repo — CLI + public signing half → completed → audit).
By default it requires **`email_sent: true`** on send (Cloudflare `EMAIL` binding
accepted the invite). On failure, check each recipient’s **`email_send_error`**
on `POST /documents/send`. Self-host without mail: add `--skip-invite-email`.

```bash
SEAL_API_KEY=seal_… pnpm run prove:golden-path
# self-host (no email yet):
SEAL_API_KEY=seal_… pnpm run prove:golden-path \
  --api https://seal-selfhost-api.<account>.workers.dev \
  --app https://seal-selfhost-web.<account>.workers.dev \
  --skip-invite-email
```

Alternate raw HTTP smoke (no CLI):

```bash
SEAL_API_KEY=seal_… node scripts/smoke-prod.mjs
# self-host:
SEAL_API_KEY=seal_… node scripts/smoke-prod.mjs --api https://seal-selfhost-api.<account>.workers.dev
```

## API keys

- Prefer **least privilege** scopes; rotate by creating a new key and revoking the old
- Plaintext token is shown **once** at create — store it in your secret manager
- Revoked keys must fail immediately on the next request

## Webhooks

- Configure an HTTPS endpoint before you send production volume
- Verify signatures on every delivery ([Webhooks](/docs/webhooks))
- Treat delivery as at-least-once — make handlers idempotent
- Alert on sustained delivery failure (check Analytics / webhook status)

## Audit & compliance

- Signing events write a sealed audit trail — see [Trust & evidence](/getting-started/trust-and-evidence)
- Export or retain audit according to your policy — do not rely on UI alone for
  legal hold without verifying retention for your plan
- **Healthcare / PHI:** Seal declines HIPAA BA workloads today — read
  [HIPAA scoping](/getting-started/hipaa) before selling to covered entities
- **EU eIDAS:** Seal is SES today — [eIDAS levels](/getting-started/eidas)
- **Privacy / subprocessors / incidents:** [Privacy & incidents](/getting-started/privacy)
- **Sensitive egress (webhooks / convert / AI):** [Sensitive egress](/getting-started/egress)
- **Enterprise SSO (SAML / OIDC):** [Enterprise SSO](/getting-started/sso)

## Email

- Hosted Seal sends from Vortex-managed senders
- **`email_sent: true`** on `POST /documents/send` means Cloudflare Email Sending **accepted** the message — not that the recipient’s inbox received it (spam, suppression, or routing can still block delivery)
- On failure, read **`email_send_error`** per recipient on the send response
- Self-host: you must configure Email Routing / verified `EMAIL_FROM` or invites
  will not leave the box ([Self-host](/docs/getting-started/self-host#email-required-for-real-invites))
- Automated proofs use a **unique plus address per run** (`SEAL_DOGFOOD_SIGNER`) so a suppressed test recipient does not flake CI; do not reuse one dogfood address for high-volume sends

## Auth & sessions

- Enforce 2FA for operators (Profile → Security)
- Review active sessions after staffing changes
- Prefer org-scoped API keys over browser sessions for automation

## Money / invoices (if you collect payment on documents)

- Amounts are **integer minor units** — never float math in your integration
- Prefer Seal’s payment config + Stripe path; do not reimplement fee allocation
  in the client

## Proof limits (not blockers)

Automated gates (`prove:golden-path`, `smoke-prod.mjs`) cover API send acceptance,
public signing ceremony (privacy/consent + viewed/signed), webhook deliveries,
completed PDF markers, and audit export — not every operational dimension:

| Area | What proof asserts | What it does **not** assert |
| ---- | ------------------ | --------------------------- |
| Email | Cloudflare Email Sending accepted invite (`email_sent` on send) | Recipient **inbox** delivery (spam, suppression, routing) |
| Analytics | PostHog on authenticated product surfaces (deferred boot) | Full product funnel dashboards or guest-signer telemetry |
| Embed | Same `/sign/$token` route with `?embed=true` (SDK iframe) | Host-app integration tests in your app — exercise `SealSigningEmbed` in staging |

Track inbox-level and analytics gaps as product tickets when they block a customer;
they are outside the agent OpenAPI golden path.
