================================================================================
                    QUICK TECHNICAL OVERVIEW
================================================================================

FLOW WHEN INVITING:
  User clicks "Invite Member"
    → InviteMemberDialog opens
    → User enters email + selects role
    → createInvitation mutation called
    → Backend checks if user exists
      → If YES: Add directly to organization_members
      → If NO: Create organization_invitations record with UUID token
    → Toast notification (invited vs. added directly)

DATA MODEL:
  organization_invitations table has:
  - email: recipient email address
  - role: admin | member | viewer (assigned role if accepted)
  - token: UUID (for magic link - not currently used)
  - status: pending | accepted | declined | expired
  - invitedBy: user ID of inviter
  - acceptedBy: user ID who accepted (null if pending)
  - expiresAt: Date.now() + 7 days
  - createdAt: timestamp

PERMISSION CHECKS:
  Only admin or owner can:
  - Create invitations (ORG_USERS_INVITE)
  - View pending invitations
  - Cancel invitations
  - Manage member roles
  - Remove members

BACKEND STRUCTURE:
  - adminMutation wrapper checks user is admin/owner
  - All organization context passed via ctx.auth
  - Database indexes optimize queries
  - TypeScript types auto-generated for frontend

================================================================================
                           CONCLUSION
================================================================================

The Seal project has a SOLID FOUNDATION for team member invitations. The
system correctly handles:
- Permission-based access control
- Direct addition of existing users
- Pending invitation tracking
- Cancellation of pending invites
- Member lifecycle management

The main gap is EMAIL INTEGRATION and ACCEPTANCE FLOW. These are clearly
separated concerns and can be added independently without affecting the
existing solid foundation.

The code is well-structured, type-safe, and follows best practices for:
- Backend permission checking
- Database query optimization
- Frontend state management
- Component composition

All code is production-ready as-is for the "create and manage" portion.
Only the "send email and accept link" portions need implementation.
